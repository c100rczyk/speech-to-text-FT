Training runs

This is the template without numbers. Run python summarize_runs.py and open runs/summary.html.

Runs

One row per folder in the runs directory. Best WER ↓ is the lowest word error rate the run reached on the validation split; the columns after it are from the same epoch. With load_best_model_at_end and metric_for_best_model: wer the model of that epoch is the one saved to final/.

WER on the validation split

WER ↓ after every evaluation. A ring marks the lowest WER of a run. The axis does not start at zero, so that the small differences between the runs can be read.

Training and validation loss

One panel per run, all on the same axes. A training loss that keeps falling while the validation loss rises means the model is memorizing the training clips (overfitting).

training loss, at every logging point validation loss, in the color of the run

Every evaluation

The numbers behind the charts. Training loss is the mean since the evaluation before. The lowest WER of each run is in bold.

Before drawing conclusions

  • These are validation numbers. The best epoch of a run is chosen on the validation split and its WER is measured on that same split, so it is a little too good, and the split is synthetic. Compare the final models on the test sets: in evaluation/ run python evaluate.py --out results/<run> --model ../ft-stt-pipeline/runs/<run>/final for every run and once for the model before fine-tuning, then python compare.py on the results.
  • The page has no confidence intervals; compare.py gives them. A difference of a few tenths of a percentage point between two runs can be chance.
  • Training loss is the loss of one batch. With gradient_accumulation_steps the trainer logs it summed over the batches of one update; it is divided back here.
